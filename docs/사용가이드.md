# Call_Record 사용 가이드

> 통화가 시작하면 자동으로 녹음되고, 끝나면 검증 리포트와 통화 내용이 파일로 남습니다.
> 이 문서는 **무엇을 할 수 있는지**, **만들어지는 파일을 어떻게 읽는지**, **어떻게 맞추는지**를 설명합니다.

---

## 1. 3분 요약

```
통화 시작 → [고지음] → 자동 녹음 → 통화 종료 → 자동 후처리
                                            ├─ 검증 리포트 .txt / .json
                                            ├─ 통화 내용 전사 .srt (+리포트에 텍스트)
                                            └─ (선택) Google Drive 백업
```

- 스위치를 켤 필요가 없습니다. **앱을 설치하고 권한만 주면 바로 동작**합니다.
- 녹음 원본은 통화 음성(양방향)을 담은 `.ogg`(Opus 24kbps) 파일입니다.

---

## 2. 화면 구성

### 2-1. 홈(설정) 화면
`Call Record` 섹션에서 Call_Record 고유 기능을 모두 켜고 끌 수 있습니다.

| 항목 | 기본 | 설명 |
|---|---|---|
| **녹음 고지음** | ON | 통화 시작 시 상대방도 들을 수 있는 신호음. 종류: `짧은 삐` / `두 번 삐` / `차임`. **미리듣기** 버튼으로 확인 |
| **고지음 종류** | 짧은 삐 | 위와 동일 (드롭다운) |
| **모든 앱 통화 녹음** | ON | 메신저 앱 통화를 전부 녹음 |
| **앱 통화 녹음 소스** | 마이크 | 앱 통화에서 어떤 소스를 쓸지 선택 (아래 5장) |
| **녹음 목록 열기** | – | 녹음·리포트 목록 화면으로 이동 |
| **검증 리포트 자동 생성** | ON | 통화 종료 후 `.txt`/`.json` 자동 생성 |
| **통화 내용 자동 전사** | ON | 온디바이스 음성 인식으로 텍스트 생성 |
| **음성 인식 모델 받기** | – | 약 40MB, 최초 1회만 필요 |
| **Google Drive 백업** | OFF | 녹음과 리포트를 Drive 폴더에 복사 |

### 2-2. 녹음 목록 화면
`설정 → Call Record → 녹음 목록 열기`

각 파일 항목에 표시되는 정보와 버튼:

| 표시 | 설명 |
|---|---|
| 아이콘 | 🎵 오디오(녹음) / 📄 텍스트(리포트) |
| 파일명 | `20261021_001530_in_01012345678.ogg` 형태 |
| 날짜·크기 | 마지막 수정 시각, 파일 크기 |
| **검증 리포트** | 해당 녹음을 분석해 `.txt`/`.json` 생성 (재생성 버튼) |
| **내용 전사** | 음성 인식까지 수행해 `.srt` 생성 (재생성 버튼) |

> 오디오 항목의 버튼을 다시 누르면 **기존 리포트를 덮어씁니다**. 전사를 새로 하려면 "내용 전사"를 누르세요.

## 3. 생성되는 파일

### 3-1. 녹음 원본 (`.ogg`)
- 포맷: OGG 컨테이너 / Opus 코덱, 24kbps, 48kHz
- 내용: 통화 음성(내 음성 + 상대 음성)
- 이름 규칙: `날짜_시간_방향_번호` (예: `20261021_001530_in_01012345678`)

### 3-2. 검증 리포트 (`.txt`) — 사람이 읽는 요약

```
Call_Record — 녹음 검증 리포트
================================================
녹음 파일    : 20261021_001530_in_01012345678.ogg
생성 시각    : 2026-10-21 00:15:30
통화 방향    : 수신 (incoming)
전화번호     : 01012345678
통화 길이    : 03:02
녹음 길이    : 03:00 (180000 ms)
포맷        : OGG/Opus
샘플레이트   : 48000 Hz
채널        : 1
비트레이트   : 24 kbps
파일 크기    : 542310 bytes

[음성 분석]
전체 RMS     : -26.4 dBFS
최대 피크    : -3.1 dBFS
노이즈 바닥  : -68.2 dBFS
음성 구간    : 23 개 / 총 12.8 %
최장 무음    : 00:41
판정        : 통화 음성으로 보임 — 녹음에 대화 내용이 포함되어 있습니다

[음성 구간 목록]
  00:00 ~ 00:12  (12.0초)
  00:14 ~ 01:03  (49.0초)
  ...

[통화 내용 전사]
안녕하세요, 내일 회의 몇 시예요?
네, 오후 3시에 가능합니다.
```

**판정 값 해석**

| 판정 | 의미 | 대응 |
|---|---|---|
| 통화 음성으로 보임 | 음성 구간이 0.5초 이상 검출됨 | 정상 |
| 오디오는 있으나 음성으로 판정되지 않음 | 소리만 있고 음성으로 보이는 구간 없음 | 앱 통화면 소스를 `스피커 출력`으로 변경 |
| 무음 또는 빈 파일 | 사실상 소리 없음 | 마이크 차단/소스 오류/녹음 실패 |
| 녹음이 너무 짧아 판정할 수 없습니다 | 1초 미만 | – |

### 3-3. 메타데이터 (`.json`)
같은 내용의 기계용 버전. 자동화 도구나 다른 프로그램에서 읽을 때 사용합니다.

```json
{
  "app": "Call_Record",
  "file": "20261021_001530_in_01012345678.ogg",
  "direction": "incoming",
  "phoneNumber": "01012345678",
  "media": { "durationMs": 180000, "codec": "OGG/Opus", "sampleRate": 48000, "channels": 1 },
  "analysis": { "overallRmsDb": -26.4, "voiceDurationMs": 23040, "verdict": "VOICE_DETECTED" },
  "voiceSegments": [ { "startMs": 0, "endMs": 12000, "durationMs": 12000 } ],
  "transcript": "안녕하세요, ..."
}
```

### 3-4. 전사 결과 (`.srt`)
자막 형식. VLC 등에서는 자막로 열 수 있고, 텍스트 편집기에서도 열립니다.

```
1
00:00:00,000 --> 00:00:12,340
안녕하세요, 내일 회의 몇 시예요?

2
00:00:14,100 --> 00:01:03,220
네, 오후 3시에 가능합니다.
```

## 4. 통화 종류별 동작

| 통화 종류 | 감지 방식 | 녹음 음질 | 비고 |
|---|---|---|---|
| **통신사 통화** (전화 앱) | `PHONE_STATE` + `InCallService` | ★★★ 양방향 (`voice-call` 소스) | 가장 정확 |
| **카카오톡 / WhatsApp / LINE / 텔레그램 등** | `InCallService` (self-managed) | ★★~ (소스에 따라 다름) | **Android 12 이상 필요** |
| **Bluetooth 헤드셋 통화** | 동일 | 통신사 통화면 양방향 | 앱 통화는 헤드셋 환경에서 약할 수 있음 |

> 앱 통화(OTT)는 통신사 통화와 같은 오디오 경로를 사용하지 않기 때문에 **상대 음성이 약하게 잡힐 수 있습니다.**
> 앱 통화 소스 선택은 5장을 참고하세요.

---

## 5. 앱 통화 녹음 소스 선택

`설정 → Call Record → 앱 통화 녹음 소스`

| 소스 | 원리 | 언제 쓰나 |
|---|---|---|
| **마이크 (기본)** | 통화용 마이크 소스(`VOICE_COMMUNICATION`) | 일반적인 경우. 상대 음성이 작게 섞일 수 있음 |
| **스피커 출력** | 스피커로 재생되는 최종 믹스(`REMOTE_SUBMIX`) | **스피퍼폰으로 통화할 때 가장 선명** |
| **앱 재생음 캡처** | 다른 앱의 재생음을 시스템 API로 캡처 | 앱이 허용한 경우에만 잡힘(대부분 앱은 차단) |
| **마이크 (음성 인식 모드)** | 잡음 억제 특화된 마이크 | 주변 소음이 심할 때 |

> **팁**: 통신사 통화는 `설정 → 오디오 → 오디오 소스 = voice-call` 을 유지하세요.
> 앱 통화와 통신사 통화는 소스를 따로 관리하므로, 하나를 바꿔도 다른 쪽에는 영향이 없습니다.

---

## 6. Google Drive 백업

1. `설정 → Call Record → Google Drive 백업` **ON**
2. `백업 폴더 선택 (Google Drive)` → 시스템 폴더 선택기에서 **Google Drive** 를 고르고 `이 폴더 사용`
3. 통화가 끝나면 녹음·리포트·자막이 Drive 폴더에 자동 복사됩니다.

- OAuth·계정 로그인은 필요 없습니다. 시스템에 이미 로그인된 Google 계정을 그대로 사용합니다.
- 복사는 **파일 단위 추가**(같은 이름이 있으면 건너뜀). Drive 쪽에서 직접 정리할 수 있습니다.
- 백업 대상: `.ogg`, `.txt`, `.json`, `.srt`

---

## 7. 통화 녹음 고지음

- 녹음이 시작되면 **통화 경로에 신호음을 주입**합니다. VoIP 앱이 통화 중 소리를 전달하는 것과 같은 경로라 **상대방도 들을 수 있습니다.**
- 통화 경로 재생이 불가능한 기기에서는 스피커 재생으로 자동 전환됩니다.
- 고지음은 녹음 파일에도 함께 담깁니다 → **"녹음이 실제로 시작되었는지" 확인할 수 있는 증거**로 쓸 수 있습니다.
- 설정에서 끌 수 있지만, **통신비밀보호법상 상대방 동의가 필요한 상황에서 끄지 않는 것을 강력히 권장**합니다.

## 8. 개인정보 보호

- 녹음 파일과 리포트는 **암호화되지 않은 평문**으로 저장됩니다. 기기 잠금(화면 잠금)·자동 잠금 설정을 켜 두세요.
- 백업은 사용자가 지정한 폴더로만 이루어지며, 앱은 어떤 서버에도 데이터를 보내지 않습니다.
  - 유일한 네트워크 사용: 음성 인식 모델 다운로드(1회), Shizuku 설치(별도 앱)
- 앱을 삭제하면 앱 내부 저장소의 모델·설정도 함께 삭제됩니다. Drive 백업 파일은 남습니다.
- 다음 버전 예정: **앱 잠금(생체/PIN)** — 녹음 목록과 리포트 열람 시 잠금 요구

## 9. 자주 묻는 질문 (FAQ)

**Q. 통화 중에 화면을 꺼도 녹음되나요?**
네. 녹음은 셸 권한 프로세스에서 동작하므로 화면 잠금 상태에서도 유지됩니다.

**Q. 두 통화가 겹쳐서 오면 어떻게 되나요?**
현재는 한 통화만 지원합니다. 두 번째 통화가 오면 첫 통화의 녹음이 종료될 수 있습니다.

**Q. 통화 기록(통화 목록)에서 번호를 못 가져옵니다.**
`InCallService` 방식(Android 12+)에서는 번호가 정상적으로 표시됩니다. Android 11에서는 `PHONE_STATE` 방식이라 번호가 비어 있을 수 있습니다.

**Q. 녹음 파일 용량이 너무 크나요?**
Opus 24kbps 기준 **1시간 ≈ 11MB** 입니다. 더 줄이려면 `설정 → 오디오 → 비트레이트`를 8~16kbps로 낮추세요.

**Q. 전사가 한국어로 정확하지 않습니다.**
현재는 경량 모델(Vosk small)을 씁니다. 정확도가 필요하면 Whisper 엔진으로 교체할 수 있는 구조로 만들어 두었습니다(v2 예정).

**Q. 통화 내용을 요약해 주나요?**
아직 요약 기능은 없습니다. 전사 텍스트(`.txt`/`.srt`)를 직접 확인하여 정리해 쓰세요. 요약 기능은 v3 예정입니다.

**Q. 통화 중 상대방이 "녹음 중이라고 하는데" 라고 하면?**
고지음이 기본 ON이므로 상대방도 인지할 수 있습니다. 법적으로는 **상대방 동의**가 기준입니다.

**Q. 앱을 업데이트하면 기존 녹음은 남나요?**
네. 녹음은 지정한 폴더에 있으므로 앱과 무관하게 남습니다. 단, **서명키가 달라지면 설치가 막히므로** 같은 키를 유지하세요.
